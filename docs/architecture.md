# الخارطة التقنية — community

## ما اكتُشف في 2026-11-15

- المجلد فارغ، وليس مستودع Git، ولا توجد تعليمات AGENTS.md أو متغيرات ربط.
- Node.js 26.12.1 وGit متاحان. PowerShell يمنع npm.ps1؛ نستخدم npm.cmd بلا تغيير سياسة النظام.
- Docker وPostgreSQL المحلي غير موجودين. اختبارات SQL ستستخدم PostgreSQL عبر PGlite مع بدائل محلية لجداول Auth وStorage؛ هذا لا يثبت عمل خدمتي Auth وStorage الفعليتين.
- اتصالات Supabase المتاحة لا تعرض مشروع community. اقتصر الفحص على أسماء المشاريع، دون فتح بيانات Lab أو Academy أو Desk.
- الرابط الذي أرسله وائل حدد المستودع العام الفارغ `hellostaffsps-max/community`. الاتصال الحالي يقرأه لكن لا يملك صلاحية دفع إليه.
- المتصفح يتيح مشروع Supabase الصحيح `feyugmltesjdwejbzgzs`. الاستعلام المباشر قبل التهيئة أكد PostgreSQL 17.11 و0 جداول عامة و0 حاويات و0 حسابات. SMTP المخصص غير مفعّل.
- Worker `community` موجود في حساب Cloudflare المحدد ومتصل بالمستودع، والنشر الآلي مفعّل؛ آخر CI فشل عند جلب المستودع. workers.dev معطل ولا يوجد custom domain.
- اختيرت Free لـgoatlab.my بموافقة وائل، ثم حُفظ نقل nameservers من Hostinger إلى `lilyana.ns.cloudflare.com` و`sid.ns.cloudflare.com` بموافقة مستقلة. آخر حالة مرصودة: انتظار انتشار DNS. لم يُنشر التطبيق ولم تُغيّر وجهة سجلّي الموقع الحالية.

## القرارات والمسار

Next.js App Router + TypeScript، Supabase PostgreSQL/Auth/Storage، واجهة عربية RTL، أرقام لاتينية وملفات ترجمة قابلة للتوسيع. لا مفاتيح ذات صلاحيات إدارية في التطبيق. جميع عمليات المستخدم تعمل بتوكنه وتخضع لـRLS حتى عند استدعاء Data API مباشرة.

راجعت [Cloudflare Next.js](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/) و[vinext](https://vinext.dev/docs/reference/differences) و[OpenNext](https://opennext.js.org/cloudflare). توصي وثائق Cloudflare الحالية بـvinext لكنه Beta ويحتاج تحققًا فعليًا. نبني Next.js قياسيًا ونختبر مسار Workers منفصلًا. لا ISR ولا ذاكرة تخزين مشتركة للمحتوى الخاص، ولا اعتماد على تحسين صور مدفوع. يمكن تغيير المحول دون تغيير مخطط البيانات.

## البيانات والعلاقات

auth.users ← profiles ← recipes ← recipe_ingredients / recipe_steps / recipe_images.
beverage_categories ← recipes. إضافة فئات مشروبات لا تحتاج جدول وصفات جديد.
profiles + recipes ← bookmarks / comments. reports يشير إلى وصفة أو تعليق واحد.
user_roles منفصل عن الملف العام وبيانات المستخدم القابلة للتعديل. moderation_actions لتتبع قرارات المشرف.

## الصلاحيات

الزائر يقرأ المنشور غير المخفي والملفات العامة فقط. العضو يكتب محتواه، ويقرأ مسوداته ومحفوظاته وبلاغاته. المشرف يرى قائمة البلاغات والمحتوى المبلّغ عنه، ويخفي المحتوى ويراجع البلاغ، ولا يحرر وصفات الآخرين. منح الدور يتم خارج واجهة التطبيق من مسؤول قاعدة البيانات. الصور في buckets خاصة، وتُقرأ عبر خادم يتحقق من RLS؛ لا روابط عامة لصور المسودات.

## ترتيب التنفيذ والتحقق

1. مخطط migration، سياسات RLS وStorage، حدود الاستخدام وعمليات SQL ذرية.
2. اختبارات مستخدمين مستقلين ومشرف وزائر؛ التصعيد وسرقة المسودات والمحافظة على الإخفاء.
3. التحقق على الخادم، الحسابات والملفات والصور والوصفات والتفاعل والإشراف.
4. واجهة RTL متجاوبة بحالات انتظار وفراغ وفشل، ثم typecheck واختبارات وبناء وفحص متصفح.
5. الربط بمشروع community المحدد، SMTP وCAPTCHA، اختبار بريد حقيقي وStorage فعلي وWorkers، ثم موافقة الإطلاق والدومين.

ألوان الزيتوني والكريمي وهوية نصية فقط معالجة مؤقتة وليست شعارًا أو هوية نهائية معتمدة.
