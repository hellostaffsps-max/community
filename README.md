# مجتمع Goat Journey

تطبيق عربي باتجاه RTL لمشاركة وصفات المشروبات، يبدأ بالقهوة والمجتمع الفلسطيني. يستخدم شعار Goat Journey الأصلي وهوية نوفمبر 2026 المعتمدة: الأصفر والفحمي والأوف وايت والأزرق، مع IBM Plex Sans Arabic وManrope محليًا. التطبيق مستقل عن Lab وAcademy وDesk؛ توثيق مصادر الأصول في `docs/brand.md`.

الصفحة الرئيسية `/` صفحة هبوط تعرّف بالمجتمع، والتصفّح والبحث والفلاتر في `/explore`، ودليل أهل القهوة في `/people`. روابط البحث القديمة على الجذر تنتقل إلى صفحة الوصفات مع حفظ الفلاتر. التسجيل مجاني بالبريد وكلمة المرور ثم رمز تأكيد من 6 أرقام، دون Google أو رسوم. لا تُضاف حسابات أو وصفات أو أرقام تجريبية إلى الإنتاج.

## نطاق النسخة

حسابات وتأكيد بريد واستعادة كلمة المرور؛ ملفات عامة بلا بريد إلكتروني؛ وصفات ومسودات ومكونات وخطوات وصورة؛ بحث وفلاتر؛ محفوظات خاصة؛ تعليقات؛ بلاغات ومراجعة وإخفاء مع سجل إجراءات. حقول جرعة البن والماء والناتج والحرارة والوقت اختيارية. لا توجد بيانات وهمية في صفحات المنتج. عند تعذر قاعدة البيانات تظهر حالة تعذر واضحة.

### تجربة القراءة والكتّاب والمتابعة

أضيفت تجربة قراءة مستلهمة من نمط Substack ضمن هوية Goat Journey: موجز للوصفات يبرز صاحب التجربة، وملف عام لكل كاتب، ومشاركة وحفظ، ودليل لاكتشاف الأعضاء. أدلة البداية المرجعية منفصلة عن وصفات الأعضاء، بمصادر معلنة؛ ليست حسابات أو منشورات أعضاء مصطنعة.

| المسار | السلوك |
| --- | --- |
| `/explore` | أحدث الوصفات العامة غير المخفية، مع البحث وطريقة التحضير وأدلة البداية |
| `/explore?feed=following` | وصفات من يتابعهم العضو فقط؛ يحتاج جلسة دخول، والقائمة الفارغة تبقى فارغة |
| `/people` | دليل الأعضاء والبحث بالاسم، بالبيانات العامة فقط ودون اسم العضو الافتراضي |
| `/people?view=following` | قائمة الحسابات التي يتابعها صاحب الجلسة؛ ليست قائمة عامة |
| `/members/{username}` | صورة الكاتب واسمه ونبذته وموقعه ووصفاته المنشورة ومشاركة ملفه؛ العدد الظاهر للوصفات يأتي من قاعدة البيانات |

المتابعة داخل التطبيق خاصة بصاحب الحساب، بحد أقصى 200 حساب. لا تعرض أعداد متابعين أو مشتركين مختلقة، ولا تنشئ اشتراكًا بريديًا أو ترسل تنبيهات بريدية أو تفرض رسومًا. التسجيل المجاني والبريد الحاليان دون تغيير.

## التشغيل المحلي

يلزم Node.js 22 أو أحدث، وnpm. على Windows استخدم `npm.cmd` إذا منع PowerShell تشغيل `npm.ps1`.

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
npm.cmd run dev
```

افتح `http://127.0.0.1:3000`. أدخل القيم العامة الصحيحة في `.env.local` محليًا، ولا ترسل أسرارًا في المحادثة. الملف مستثنى من Git. وضع التطوير يتصل بالمشروع المحدد إن كانت قيمه موجودة؛ عمليات الواجهة تكتب بيانات حقيقية، وليست محاكاة.

| المتغير | الاستخدام |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | عنوان مشروع community المحدد أو Supabase المحلي في التطوير |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | المفتاح القابل للنشر فقط، بصيغة `sb_publishable_…` للمشروع السحابي |
| `APP_ORIGIN` | أصل التطبيق بلا مسار ولا شرطة أخيرة؛ HTTPS عند الإطلاق |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | مفتاح Turnstile العام؛ محفوظ في بناء Cloudflare |
| `ALLOW_PUBLIC_SIGNUP` | `true` للإنتاج المعتمد؛ الافتراضي والمحلي `false` |

المفتاح السري لـTurnstile محفوظ في إعداد CAPTCHA في Supabase Auth فقط؛ لا يضاف إلى ملفات المتصفح. حُفظ فتح التسجيل في Supabase وبناء Cloudflare بعد اعتماد المالك، وتأكد `disable_signup=false` واشتراط تأكيد البريد وغياب Google. الدخول المجهول معطل. يرفض التطبيق فتح التسجيل إذا غاب مفتاح الحماية العام حتى لو كان علم الفتح `true`.

## قاعدة البيانات

المصدر المقروء `supabase/schema.sql`، والنسخة التنفيذية `supabase/migrations/20261115000204_community_foundation.sql`. يوجد اختبار يمنع اختلافهما. أنشئت migration بواسطة Supabase CLI. هي تهيئة أولى مرة واحدة وليست سكربتًا لحذف وإعادة إنشاء قاعدة موجودة. يحفظ CLI تاريخ التطبيق، فلا يُعاد تنفيذ migration مطبقة.

عند توفر Docker يمكن تشغيل بيئة Supabase محلية كاملة:

```powershell
npm.cmd run db:start
# بعد ضبط .env.local لقيم البيئة المحلية وتشغيل migration عبر CLI:
npx.cmd supabase db reset --local
```

`db reset --local` يمسح قاعدة التطوير المحلية فقط. لا تستخدمه على بيانات مطلوبة. أدوات SMTP المحلية تعرض رسائل الاختبار دون إرسالها إلى بريد حقيقي. Docker غير متاح في البيئة التي أُنشئ فيها هذا المشروع؛ لذلك اختبارات RLS تستخدم PostgreSQL داخل PGlite ولا تدّعي اختبار خدمات Supabase كاملة.

طُبّقت التهيئة السحابية بالفعل عبر SQL Editor داخل `community` في معاملة واحدة، بعد الموافقة والتحقق أن المشروع فارغ. لا تُعد تنفيذها. تم التحقق من 11 جدولًا محميًا بـRLS وحاويتين خاصتين ومنع الزائر من حفظ الوصفات. لا يوجد سكربت يمنح أي مستخدم دور مشرف تلقائيًا.

أُعد اتصال MCP باسم `supabase` مقصور على مشروع `feyugmltesjdwejbzgzs`، وتأكد تسجيل الدخول الآمن عبر OAuth. يحتوي سجل الترحيلات السحابي الآن إضافة المتابعة `20261121014640`، لكن التهيئة السابقة `20261115000204` ما زالت غير مسجلة فيه رغم تطبيق مخططها سابقًا. قبل أي `db push` لاحق، طابق المخطط القائم ثم سوِّ سجل التهيئة السابقة باستخدام أمر إصلاح سجل الترحيلات بعد مراجعة `--help` للنسخة المثبتة واستهداف community صراحة. لا تعالج فرق التاريخ بإعادة تنفيذ التهيئة أو إعادة إنشاء الجداول. منح دور المشرف يحتاج تحديد المستخدم والموافقة عليه عبر قناة إدارية موثوقة.

### إضافة المتابعة الخاصة

المصدر المقروء `supabase/community-social.sql`، والملف التنفيذي المطابق `supabase/migrations/20261121014640_community_member_follows.sql`. تضيف هذه migration جدول `member_follows` وسياسات RLS وحارس الإدخال، وتعتمد على تهيئة community السابقة. لا تستبدل `schema.sql` ولا تعيد إنشاء جداول التطبيق.

طُبّقت هذه الإضافة وحدها وسُجّلت بالنسخة `20261121014640` على مشروع **community / `feyugmltesjdwejbzgzs`** بعد الموافقة. طُوبق SQL المطبق مع المصدر المحلي دون اختلاف. لا تُعد تنفيذ migration مطبّقة، ولا تستخدم `db reset` على السحابة، ولا تدفع تاريخ migrations كاملًا قبل تسوية سجل التهيئة القديمة الموضح أعلاه. أي إضافة لاحقة تُراجع وتُنفذ على المشروع المحدد فقط، دون إعادة إنشاء التهيئة القائمة.

أكد فحص المخطط السحابي تفعيل RLS وثلاث سياسات للمستخدم المصادق تحصر القراءة والإضافة والحذف بصاحب العلاقة، مع اشتراط تأكيد الحساب عند الإضافة. سماح `SELECT` للزائر يتيح فحص وجود الميزة دون سياسة تسمح له بقراءة العلاقات، وأعاد طلب REST المجهول الحي صفر صفوف. لا توجد صلاحية كتابة للزائر، ولا `UPDATE` للمستخدم؛ إدخال المستخدم مقصور على عمودي العلاقة دون الطابع الزمني. حارس الإدخال يعمل بصلاحية المستدعي و`search_path` فارغ، ويقفل الملف الشخصي بـ`FOR NO KEY UPDATE` لفرض حد 200 متابعة و240 إنشاء/ساعة، دون منح تنفيذ مباشر للدالة. تحقق الفحص أيضًا من المفتاح المركب ومنع متابعة الذات والمفاتيح الخارجية ذات الحذف المتتابع والفهرس. تثبت اختبارات قاعدة البيانات عزل المستخدمين، لكن لم تُجرَ كتابة متابعة أو تجربة حية بين حسابين على الإنتاج. لا يتطلب ذلك مفتاحًا إداريًا في التطبيق أو تعديل إعدادات البريد.

## الأمان

- RLS على الجداول المكشوفة. القراءة العامة للوصفات المنشورة غير المخفية فقط، مع استثناء صاحب المحتوى وصلاحية مراجعة البلاغ المحددة. المسودات لا يقرأها المشرف لمجرد كونه مشرفًا.
- الصور في حاويتين خاصتين؛ سياسة القراءة تتبع الوصفة. واجهة `/api/media` تستخدم جلسة صاحب الطلب، ولا تستعمل تجاوزًا إداريًا أو روابط عامة للمسودات.
- أذونات صريحة، ملكية غير قابلة للتغيير، وعدم الثقة في role من metadata. الملفات العامة لا تحتوي البريد. المحفوظات خاصة حتى بالنسبة للمشرف.
- حفظ الوصفة ومكوناتها وخطواتها في معاملة واحدة، مع رقم إصدار يمنع الكتابة فوق تعديل أحدث. لا يمكن نشر وصفة بلا مكوّن وخطوة، حتى عبر Data API.
- تحقق Zod على الخادم، قيود SQL، فحص Origin للطلبات المعدّلة، حد لحجم الجسم حتى مع streaming، وأسماء عشوائية للصور. صور JPG/PNG/WebP فقط مع فحص ترويسة المحتوى وحد حجم؛ الفحص ليس فك ترميز كاملًا للصورة ولا مضاد فيروسات.
- حدود قاعدة البيانات: 20 وصفة/يوم، 30 تعليقًا/ساعة، 60 تعديلًا/ساعة، 10 بلاغات/يوم، 120 حفظًا/ساعة، 50 رفع صورة/يوم. التخزين يحد عدد الملفات لكل وصفة/ملف شخصي إلى 3 لتقييد الملفات اليتيمة.
- المتابعة الخاصة: 200 حساب كحد أقصى، و240 عملية إنشاء متابعة/ساعة؛ الملكية من جلسة الدخول الموثّقة. يرفض طلب إضافة المتابعة حقول الملكية الزائدة، ويقيّد الحذف بالمستخدم الموثّق والهدف المحدد دون اعتماد حقول الجسم أو معاملات الرابط لتحديد المالك.
- صفحات الجلسة وبيانات الصور دون cache. لا يُخزّن HTML المصادق عليه في CDN. السجلات تحتوي رمز خطأ ومعرّف طلب فقط، دون المحتوى أو البريد أو المفاتيح.

## Cloudflare وربط GitHub

مسار Next.js المحلي باقٍ للمقارنة. أضيف مسار vinext الذي توصي به وثائق Cloudflare الحديثة لهذا النوع من المشاريع؛ حالته Beta. يعتمد القرار النهائي على نجاح بناء Worker واختبار جلسات Auth ورفع الصور فعليًا. OpenNext بديل عند ظهور عدم توافق. لا يستخدم التطبيق ISR أو تحسين الصور، ولا ينشئ KV أو R2 أو Images أو خدمة إضافية.

- `vite.config.ts`: إعداد App Router على Workers.
- `cloudflare.config.ts`: Worker اسمه `community`، ومدخل vinext، وStatic Assets فقط.
- `npm run build:vinext`: يبني محليًا.
- `npm run start:vinext`: معاينة Worker محليًا.
- أمر النشر يتطلب مراجعة وموافقة منفصلة؛ وجوده لا يعني أنه نُفّذ.

للمعاينة على المنفذ 4173، أنشئ `.env.production.local` (مستثنى من Git) بالقيم `APP_ORIGIN=http://127.0.0.1:4173` و`ALLOW_PUBLIC_SIGNUP=false`، ثم شغّل `npm run build:vinext` و`npm run start:vinext -- --host 127.0.0.1 --port 4173`. قيم `NEXT_PUBLIC_*` تُثبّت أثناء البناء. يقرأ `cloudflare.config.ts` متغيري `APP_ORIGIN` و`ALLOW_PUBLIC_SIGNUP` من بيئة البناء ويضيفهما كـtext bindings إلى Worker؛ غيّر الأصل إلى العنوان الإنتاجي المعتمد قبل بناء إصدار النشر. يرفض التطبيق أي Origin خارجي غير HTTPS، ويسمح HTTP لعناوين loopback المحلية فقط. يفحص `typecheck` ملفات المصدر عبر `tsconfig.check.json` دون مخرجات المسارات المتعارضة بين Next.js وvinext؛ بناء Next.js يفحص أنواع مساراته المولّدة.

## الدومين والبريد والإطلاق

اختيرت خطة Cloudflare Free بموافقة المستخدم، واكتمل انتقال خوادم الأسماء إلى `lilyana.ns.cloudflare.com` و`sid.ns.cloudflare.com`. استُبدل سجل الجذر القديم `A 2.57.91.91` بدومين Worker المخصص بعد اعتماد الإتاحة العامة. بقي `www` سجل CNAME إلى `goatlab.my` مع Proxy، وتحوّله قاعدة Cloudflare `community canonical HTTPS` إلى الأصل الآمن مع حفظ المسار ومعاملات الرابط. تحول القاعدة أيضًا HTTP على الجذر إلى HTTPS.

حُفظ Site URL في Supabase على `https://goatlab.my`، وعنوان الرجوع المسموح `https://goatlab.my/auth/callback`. حُفظ SMTP وTurnstile وتأكد رفض Supabase لطلب دخول بلا CAPTCHA. اختبار وصول رسالة حقيقية وإكمال جلسة حساب واستعادة كلمة المرور يتطلب تجربة المالك المباشرة؛ لا يُعتبر حفظ SMTP أو نجاح البناء دليلًا على وصول البريد.

اعتُمد Resend Free دون شراء. تم توثيق `auth.goatlab.my` وحفظ SMTP في Supabase للإرسال من `noreply@auth.goatlab.my`، وحفظ قالب التأكيد العربي برمز من 6 أرقام صالح لعشر دقائق. Turnstile Managed مفعّل لـ`goatlab.my`، وكلمة المرور 12 حرفًا على الأقل. تفاصيل الإعداد وحدود الاختبارات في `docs/email-setup.md`.
