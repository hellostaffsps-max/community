# التشغيل والنسخ والاستعادة

## حدود المسؤولية الحالية

التطبيق لا ينشئ خدمة مدفوعة أو يفعّل إضافة أو مراقبة خارج الموارد المعتمدة. توثيق الإجراءات لا يعني تنفيذها. أي منح لدور مشرف، إعداد خدمة إرسال، أو نشر وربط نطاق، يحتاج مراجعة الفعل المحدد ضمن موافقات المالك.

## النسخ الاحتياطي

قاعدة PostgreSQL وملفات Storage موردان منفصلان. تصدير قاعدة البيانات لا يحفظ بايتات الصور. قبل أي نشر إنتاجي: تحقق من خصائص النسخ الفعلية في خطة Supabase المستخدمة؛ لا تفترض توفر PITR أو نسخة يومية على Free.

1. صدّر مخطط قاعدة البيانات والأدوار والبيانات بواسطة طريقة Supabase الرسمية المناسبة للمشروع، إلى وجهة محمية يحددها المالك. احفظ الأسرار خارج السجل وGit. سجّل وقت النسخة وإصدار migration ونتيجة التصدير.
2. صدّر محتويات `recipe-images` و`avatars` عبر Storage API مخول إداريًا، مع manifest للمسارات والأحجام وSHA-256. يجب أن تبقى الصور الخاصة خاصة في وجهة النسخة.
3. اجعل retention والتشفير والجهة التي تستطيع استعادة النسخة قرارات صريحة. المقترح اليومي وقبل المهاجرات، لكن الجدولة لم تُنشأ.
4. احتفظ بتعريفات migrations والسياسات في Git، لكن لا تضع dump المستخدمين أو الصور أو مفاتيح الخدمة فيه.

## تجربة الاستعادة المطلوبة

استخدم بيئة محلية منفصلة أو وجهة استعادة معتمدة صراحة. أعد schema ثم البيانات والملفات مع مساراتها. تحقق من عدد الصفوف وchecksum الملفات، ومراجع الصور، ومن أن حاويات Storage بقيت خاصة. اختبر المسودات بواسطة مستخدمين مختلفين، وتسجيل الدخول، وحفظ الوصفات والتعليقات. وثّق زمن الاستعادة والبيانات المفقودة إن وجدت. لا تغيّر وجهة الإنتاج حتى اعتماد النتيجة. لا توجد استعادة سحابية مختبرة حاليًا.

## مراقبة الأخطاء والاستهلاك

قبل الإطلاق راجع Worker Logs وTraces وحدود الاحتفاظ وما إذا كانت مفعّلة؛ كانت معطلة عند الفحص. سجلات التطبيق المنقّحة تسجل نوع الحدث ورمز الخطأ ومعرف طلب فقط. راقب أخطاء 5xx وAuth وStorage وزمن الاستجابة، وأعداد requests وCPU ونقل البيانات وحجم DB/Storage. أي تفعيل أو تكلفة إضافية تتطلب الموافقة عند انطباقها.

فشل تنظيف ملف قديم يسجل `media_cleanup_pending`؛ عالج الملفات اليتيمة بعد مقارنتها بمراجع DB وقبل حذف أي محتوى مطلوب. عند إساءة استخدام التسجيل، أغلقه في التطبيق وفي إعدادات Auth مع مراعاة موافقة تغيير الصلاحيات. حد التطبيق وحده لا يمنع استدعاء Auth API مباشرة.

## الرجوع عن إصدار

راجع نسخة Worker السابقة قبل النشر، واختبرها مع schema الجديدة. الرجوع عن كود Worker لا يرجع migration. استخدم migration تصحيحية بعد فحص البيانات؛ لا تحذف جداول لإصلاح مشكلة. سجّل أي تغييرات على DNS أو redirects لتكون العودة دقيقة وبموافقة المالك.
