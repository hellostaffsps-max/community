# التحقق الفعلي

## تطوير مساحة المجتمع ومحرر الوصفات

- أصبح إدخال الوصفة أربع مراحل: الفكرة والأداة، المقادير، التحضير، والمراجعة. أضيفت قوائم للأدوات والمكونات والوحدات والطحن، مع اختيار مخصص يحافظ على قيم الوصفات السابقة.
- يدعم المحرر الأرقام العربية والفارسية والعشرية، ويحوّل الدقائق والثواني إلى عدد صحيح للـAPI. تُعرض أخطاء الحقول في مرحلتها، وتُحذف الصفوف الفارغة فقط؛ لا يُتجاهل مكوّن أُدخلت كميته دون اسمه. المسودة تقبل وصفة غير مكتملة، والنشر يتطلب المكونات والخطوات والأداة.
- أضيفت معاينة للوصفة والصورة قبل الحفظ، وإعادة ترتيب الخطوات، ونسبة الماء إلى البن، ومؤشر التعديلات غير المحفوظة وتنبيه عند المغادرة. يستمر حفظ رقم النسخة لمنع الكتابة فوق تعديل أحدث.
- للصفحات الداخلية قائمة جانبية على الحاسوب، وتنقّل سفلي بخمسة أقسام على الهاتف، وحالات تحميل وروابط نشطة. حُسّنت صفحات الحساب والاستكشاف وتفاصيل الوصفة ضمن هوية Goat Journey الحالية.
- نجحت الاختبارات الـ42 أولًا، ثم اختبارات المحرر السبعة بعد إضافة اختبار توجيه الخطأ إلى المرحلة الصحيحة. نجح فحص TypeScript.
- اختُبرت الواجهة محليًا ببيانات عرض منفصلة: التحقق من الحقول الفارغة، اختيار الأداة والطحن والمكوّن والوحدة، المقادير العربية، الوقت، إضافة الخطوات وإعادة ترتيبها، المراجعة، والعودة مع الاحتفاظ بالمدخلات. لا توجد أخطاء console مرصودة في فحص التفاصيل.
- فُحص المحرر والحساب والتفاصيل والاستكشاف عند عرض 320 و390 بكسل دون تمدد أفقي. صفحة العرض المؤقتة أُزيلت قبل بناء الإنتاج. لم تُنشأ وصفات اختبارية في قاعدة الإنتاج، ولم تُعدّل مسودة المالك المفتوحة في Chrome.
- نجح بناء Next.js الإنتاجي وفحوص HTTP الثمانية على النسخة المبنية محليًا: الصفحات، حماية الحساب، حالة التسجيل المحلية، رفض Origin خارجي، رفض كتابة الزائر، ومسار الصورة. بناء vinext المحلي توقف يدويًا بعد اجتياز تحليل مراجع العميل بسبب بطئه؛ بناء Cloudflare الآلي هو فحص توافق نسخة النشر، ولا تُعد المحاولة المحلية بناء Worker ناجحًا.

## تفعيل التسجيل المجاني — 2026-11-20

- نُفذت رحلة بريد وكلمة مرور ثم رمز من 6 أرقام، مع دعم الأرقام العربية والفارسية، انتهاء الرمز بعد عشر دقائق، وإعادة إرسال بعد 60 ثانية. لا رسوم أو Google.
- نجح فحص TypeScript و36 اختبارًا في ثلاثة ملفات، بما فيها 13 اختبارًا لحدود التسجيل والتحقق وCAPTCHA وعدم تسريب الجلسة. نجح بناء Next.js وبناء vinext، ونجحت فحوص HTTP الثمانية على معاينة Worker المحلية بوضع التسجيل المغلق.
- أصلحت نتيجة اختبار JSON غير محددة النوع التي منعت بناء Next.js الأول، ثم نجح البناء الكامل.
- نجحت فحوص HTTP الثمانية أيضًا على Next.js المحلي مع واجهة التسجيل المفتوحة ومفتاح Turnstile الاختباري الرسمي. فُحصت صفحات التسجيل والتأكيد والدخول بصريًا عند عرض 390 و320 بكسل دون تمدد أفقي؛ لم يُرسل طلب إنشاء حساب أو بريد من هذه المعاينة.
- توثيق Resend للنطاق Verified / Ready. سجلات البريد الثلاثة المعتمدة محفوظة في Cloudflare. SMTP المخصص محفوظ في Supabase، والمفتاح مقيد بالإرسال من النطاق المعتمد.
- قالب التأكيد العربي محفوظ ومعاين في Supabase. حُفظ طول الرمز 6 وصلاحيته 600 ثانية والحد الأدنى لكلمة المرور 12؛ تأكيد البريد مفعّل.
- أُنشئ Turnstile Managed لـgoatlab.my دون pre-clearance. حُفظ تفعيله وسره في Supabase. طلب دخول بعنوان اختباري غير موجود وبلا CAPTCHA رُفض بـHTTP 400 و`captcha_failed`؛ لا مستخدم أو بريد نتج عنه.
- نجح بناء Cloudflare للنسخة `47f312ea813aba62ba71e8325d6dcc51a71575a6` عبر `d53ea513-af69-40fe-b28d-b7241133a1bf`. وصلت صفحة `/auth/verify` الجديدة للموقع، وتأكد وجود مفتاح Turnstile الحقيقي في ملفات JavaScript العامة، مع HTTP 200 وno-store.
- حُفظ فتح التسجيل في Supabase، وأكدت إعداداته العامة `disable_signup=false` و`mailer_autoconfirm=false` و`external.google=false`. ظلت خيارات الدخول المجهول وربط الحسابات اليدوي معطلة في اللوحة. نُشرت قيمة `ALLOW_PUBLIC_SIGNUP=true` بنجاح مع النسخة `3b4a194` عبر بناء Cloudflare `2c85737e-59c7-44d9-836a-5215debb7cc4`.
- عُوين نموذج التسجيل المجاني على الدومين الحي مع Turnstile. أعادت صفحتا التسجيل والتأكيد HTTP 200 و`private, no-store`، ورُفض طلب التسجيل دون CAPTCHA بـHTTP 400 قبل إنشاء حساب أو إرسال بريد.
- أكمل المالك تجربة التسجيل وتأكيد البريد بنفسه، وأفاد أن الحساب فتح. تأكدت جلسة الدخول في المتصفح بظهور رابط «حسابي» ومحرر الوصفات المحمي في `/recipes/new`. لم تُجمع كلمة المرور أو رمز التأكيد في المحادثة أو المستودع.
- لم تُختبر استعادة كلمة المرور بحساب حقيقي بعد. لم يتم شراء أو تفعيل خطة مدفوعة.

ما يلي سجل تاريخي؛ لا تُقرأ حالات البريد والدومين القديمة كحالة راهنة.

## إتاحة الدومين بعد اعتماد المالك

- أُتيح `https://goatlab.my` بربطه مباشرة بـWorker `community`. أُزيل سجل الجذر السابق `A 2.57.91.91` ضمن الاستبدال المعتمد، وبقي `www` سجل CNAME إلى الجذر مع Proxy وTTL Auto.
- حُفظت قاعدة Cloudflare `community canonical HTTPS`؛ أثبتت طلبات HTTP الفعلية أن `https://www.goatlab.my` و`http://www.goatlab.my` و`http://goatlab.my` تعيد 301 إلى HTTPS على الجذر، مع حفظ المسار ومعاملات الرابط.
- حُفظ Site URL في Supabase على `https://goatlab.my` وأُضيف `https://goatlab.my/auth/callback` إلى Redirect URLs، ثم تحققنا من القيم المحفوظة.
- الصفحة الرئيسية السحابية تعيد HTTP 200 وتعرض المجتمع العربي مع `Cache-Control: private, no-store`. ملف CSS يعيد 200 بنوع صحيح.
- صفحة التسجيل تعرض الإغلاق؛ طلب إنشاء الحسابات يعيد 503، وكتابة الزائر 401، والطلب من Origin خارجي 403، ومسار الصورة غير الصالح 400. صفحة الحساب تحوّل الزائر إلى تسجيل الدخول. callback بلا رمز يعيد 303 إلى صفحة الدخول على الدومين الصحيح.
- إعدادات Supabase الحية ما زالت `disable_signup=true` و`external.google=false`، وAuth وData API يعيدان 200. لم يُفتح التسجيل ولم يُعد SMTP أو Google ولم يحدث شراء.
- أُضيف الدومين إلى `cloudflare.config.ts` لضمان استمرار الربط مع النشر الآلي من GitHub. اختبار TypeScript ناجح. آخر بناء قبل هذا التغيير للنسخة `cdc0ae4` نجح خلال 56 ثانية (`bd654952-0216-4cd1-9252-737a7a8c0ec1`، إصدار `62009893`).

النتائج أدناه توثق المراحل السابقة، بما فيها الحالة قبل الموافقة على النشر العام.

## إعادة التحقق بعد إلغاء تسجيل Google

- النسخة المحلية و`main` على GitHub متطابقتان عند `166243b1641fd555575bbde577becd72fa2d5227`. لم تُرفع ميزة تسجيل Google.
- Cloudflare نشر هذه النسخة بنجاح عبر البناء `cf751072-485f-48f2-a15c-1121127cf329`؛ الإصدار النشط يبدأ بـ`b19d66fc`، والحالة Ready خلال 1m 9s.
- اتصال GitHub وبيئة البناء صحيحان: المستودع `hellostaffsps-max/community`، وأوامر فحص الأنواع والاختبارات ثم `npm run deploy:vinext`، وعنوان Supabase للمشروع المحدد. قيم التشغيل `APP_ORIGIN=https://goatlab.my` و`ALLOW_PUBLIC_SIGNUP=false`.
- اكتمل انتقال خوادم أسماء `goatlab.my` إلى `lilyana.ns.cloudflare.com` و`sid.ns.cloudflare.com`؛ تؤكد استعلامات DNS ولوحة Cloudflare أن النطاق نشط. هذا لا يعني ربطه بالـWorker.
- فحص Supabase الحي: Auth وData API يعيدان HTTP 200، و`disable_signup=true` و`external.google=false`.
- نجح TypeScript والاختبارات الـ23 وفحوص HTTP الستة على معاينة Worker بعد التراجع عن Google.
- أُصلح سطر مدمج في `.env.local` لتكون قيمة `ALLOW_PUBLIC_SIGNUP` هي `false` صراحة. أصبح فحص الاتصال يفشل إذا لم يكن التسجيل مغلقًا في التطبيق وSupabase أو إذا تفعّل Google.
- المتبقي للإتاحة العامة: ربط النطاق بالـWorker، وضبط Site URL وقائمة Redirect URLs في Supabase؛ آخر قراءة أظهرت `http://localhost:3000` وقائمة فارغة. لم تُحفظ هذه التغييرات حتى اعتماد خطوة الإتاحة العامة.
- البريد مؤجل والتسجيل مغلق بطلب المالك؛ لم يحدث شراء أو إنشاء خدمة إضافية. تاريخ migration السحابية عبر CLI ما زال يحتاج مصادقة CLI قبل أي `db push` لاحق؛ لا تُعد تشغيل التهيئة الحالية.

الجدول التالي يحتفظ بنتائج مراحل التنفيذ السابقة؛ الحالة الأحدث مذكورة أعلاه.

## ما لم يُثبت في مرحلة التنفيذ الأولى (سجل تاريخي)

لم تُختبر رحلة مستخدم حقيقي من رسالة التأكيد إلى إعادة تعيين كلمة المرور. PGlite يختبر PostgreSQL الحقيقي وRLS لكن جداول Auth وStorage فيه بدائل اختبارية، وليس خدمات GoTrue/PostgREST/Storage الفعلية. لا توجد تجربة استعادة نسخة سحابية. نجح رفع Worker في Cloudflare بلا عنوان عام (`No targets deployed`)، لذلك لم يُختبر HTTP على النسخة السحابية. البريد مؤجل والتسجيل مغلق بطلب المالك. يجب تحديث هذا التقرير عند نجاح الاختبارات المتبقية بدل افتراض نتائجها.
